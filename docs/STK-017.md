# STK-017 — Worker, monitoring and encrypted recovery

**Status: Backlog + Blocked / PARTIAL.** Independent implementation and local synthetic recovery verified. External B2 setup, custody, delivery of owner alerts and target-host acceptance remain gated. No purchases, external deployment, notification delivery or B2 calls were made.

## Delivered controls

- Persistent PostgreSQL jobs retain leases, bounded retries and idempotency. Session-level advisory lock prevents a second worker reclaiming a job while the first process is still alive beyond the five-minute recovery lease; crashes release the lock. Worker writes atomic health timestamps, emits allowlisted status events and reports unhealthy on failures/staleness.
- API exception/request logging omits exception text, paths, query strings, cookies and bodies. Proxy logs contain only status/duration; API access logging is disabled. Synthetic request canary and access key were absent from sampled runtime logs. This is tested scoped logging, not a claim about all host/system logs.
- `scripts/backup_restore.py` streams dumps and table fingerprints instead of buffering the dataset. Exclusive 0600 dump creation; quiesced source comparison; isolated transactional restore and every research-table checksum; schema revision check. Existing migrations and fixtures unchanged.
- `scripts/operate.py backup` serializes operations, stops writers, verifies a dump locally, restarts writers even after dump failure, writes an encrypted restic snapshot, downloads that exact snapshot, checks its dump hash and restores it into another disposable database. Only then is the success receipt updated. Receipt contains UTC epoch timestamps, snapshot ID, dump size/hash, schema, code/image identities and table hashes. Optional STK_RECOVERY_BUNDLE adds operator-prepared configuration recovery material; it must be supplied and tested before host acceptance. No live PGDATA backup.
- Automatic backups never prune. Separate `prune` requires STK_PRUNE_AUTHORIZED=true, a recent verified receipt, existence of that snapshot and a full repository check. Policy matches STK-008: 7 daily / 4 weekly / 3 monthly. Run with separately held owner pruning credentials off the VPS. Validate B2 upload/lock permissions and deletion resistance before relying on restricted credentials; no Object Lock claim.
- Monitoring checks service state/health, failed/late jobs, worker heartbeat, disk below 25%, Linux available memory below 10%, backup age above 26 hours and (when APP_ORIGIN is set) HTTPS reachability/certificate expiry within 14 days. A local explicitly configured STK_ALERT_EXECUTABLE receives allowlisted JSON via stdin on state changes. No destination is selected or contacted. Host outage requires an independent dead-man monitor; local monitoring cannot detect its own dead host.
- Prepared systemd timers: nightly backup 20:30 UTC (02:00 IST next day), five-minute health checks. Timers are not installed/enabled. They run as host root for Docker administration; runtime containers never receive Docker access or backup credentials.
