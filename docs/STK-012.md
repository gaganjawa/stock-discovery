# STK-012 — CI and reproducible builds

Status: Done. Completion recorded: 11 October 2026. Owner: Codex. Release: v0.1.

The GitHub Actions workflow runs on pushes to main and pull requests with read-only repository permissions. It validates the three contracts, tests the API/worker, builds the UI, builds all Compose images and checks the running API, JavaScript asset, PostgreSQL SELECT 1, worker cycle and database URL interpolation. Failure logs are retained in the run; disposable CI containers are removed on completion.

Python direct requirements live in backend/requirements.in. The generated requirements.txt locks transitive versions and distribution hashes across platforms for Python 3.12. Install with `python -m pip install --require-hashes -r backend/requirements.txt`. Regenerate deliberately with uv 0.12.16: `uv pip compile backend/requirements.in --python-version 3.12 --universal --generate-hashes -o backend/requirements.txt`. Review and validate lock changes before committing.

The frontend uses the committed package-lock.json through npm ci, including inside Docker. Vite was updated to 7.3.7 to resolve the reported advisories. Node and Python CI versions are recorded in .node-version and .python-version. Official container image indexes and GitHub Actions are pinned to immutable digests/commits. Update these deliberately with dependency upgrades. This fixes dependency inputs; it does not claim bit-identical image output across architectures or runner updates.

The existing .env.example contains synthetic local defaults only. Copy to .env for local overrides; never commit credentials. Compose defaults work without copying. Published ports bind to 127.0.0.1. DATABASE_URL now uses Compose interpolation, rather than passing literal variable expressions. Custom database passwords must be URL-safe (or percent-encoded in an explicitly configured URL). Build contexts exclude environment files, Git metadata and local dependency directories.

Local checks: fresh hash-verified Python 3.12 install, three API/worker tests and fresh npm ci/production build passed. npm audit reported zero vulnerabilities. Full container execution is assigned to CI because the local Docker daemon and Compose plugin are unavailable. Reproduce the container smoke test with Docker Compose v2:

```sh
docker compose up --build -d
python3 scripts/smoke_compose.py
docker compose down
```

For smoke tests with non-default ports, export API_PORT and WEB_PORT in the invoking shell as well as configuring Compose. No schema, deployment or next-ticket work is included. The user will update the hosted board manually.
